# 审稿结果如何进入下一轮工作

0.9.0 提供一条有边界的闭环：已有审稿回复 → 结构化问题计划 → 授权文字修改 → 自动只读复核 → 作者核验。
这是通过当前 DSH 模型和工具执行的工作流，不是独立的论文判分器，也不是后台常驻代理。

## 先准备

- 已安装插件，在有实际路径的工作区及**同一个审稿会话**中操作。
- 普通模型对话能用，宿主工具能读取稿件。新版本写入权限由 DSH 控制。
- 准备自己的稿件路径；若多版本并存，请明确哪份是本轮基线。
- 先发送或保存并清空输入框中的其他草稿。闭环直接运行按钮不会覆盖这些草稿。
- 确认审稿资料允许交给当前模型处理；不要将保密审稿记录或敏感数据提交公共仓库。

## 1. 接收现有审稿回复

在“开始”下方展开“已有审稿结果？接着修改与复核”。选取审稿回复，预览后点击“整理这份审稿结果”。
可以接续原先通过普通提示词得到的审稿结果，不要求先使用专门命令。
选择器只列已加载窗口内最近 12 个已结束轮次的最后一条完整助手正文；不会读取推理块、流式中间内容或中断残片。
未找到旧回复时，先在 DSH 会话加载对应历史消息；不是通过扫描文件名猜测审稿内容。

整理任务会读原稿、识别意见编号、类别、优先级、位置、建议和证据。
只分析，不改稿。文件缺失、不能读全文、原稿身份不明确时，应返回阻碍，先补材料。
单份所选回复最多 24,000 字符；单阶段结果最多 48,000 字符、60 条意见，超出时需要分批，不能静默丢弃意见。

## 2. 授权一轮修改

计划返回后查看每条意见，填写具体范围，例如：

```text
仅处理 R1.1 和 R2.3，修改引言与讨论的文字表达。
保留数据、实验结果、结论和其他章节，不新增未核验引文。
```

点击“授权本轮修改并执行”会使用当前模型额度。默认勾选“修改后自动只读复核”，最多发送两次任务：
先生成独立修订版本，再读取原稿与该版本逐项复核。取消勾选后，修改完成会停下，可手动“继续只读复核”。
原始意见和问题编号必须保留；需要实验或作者决定的事项不得自动标为解决。
实际模型写文件行为仍受 DSH 工具权限约束；结构校验不能替代对工具行为和文件内容的审查。

## 3. 看懂返回结果

插件回收真实完成的助手回复，并保存其会话、用户消息序号、助手消息序号和轮次。
不是仅记录“模型结束了”或“多了一个文件”。

- 未解决：本轮没有解决，或缺少必要条件。
- 部分解决：模型认为只解决一部分，需要核验。
- 模型认为已解决：必须有对应新稿位置及证据文本，仍待作者确认，不会自动确认研究阶段。

“历史轮次与证据”保留各阶段结果；“导出本闭环记录”下载 JSON 供备份查看。
需要额外处理的文字问题可再授权一轮。两轮到达上限后停止，不通过不断自评分数追求虚假的合格。
复核发现新增问题时可以保留为新编号，不能消失或改写原问题。

## 自动执行何时停止

- 模型失败、轮次中断、没有对应完整消息，或不能关联到本任务。
- 输出没有唯一的 `research-loom-result` JSON、阶段不符、缺字段或超出上限。
- 删除原意见编号、改写原文/类别、声称已解决却不给证据、复核版本与实际修订阶段不一致。
- 出现新的用户消息、输入框有新草稿、设置不可写、现有任务冲突。
- 收起工作台、离开当前会话/工作区、刷新或关闭页面。续行许可只在当前组件生命周期有效，不会跨重启自行恢复。

“暂停后续自动执行”只撤销后续任务许可；已经发送的任务请在 DSH 中停止。
没有找到对应回复时不会无限自动重试。检查发送状态，必要时点击“结束等待，不再自动衔接”，然后选正确的完成回复重新整理。
结果格式不合格时保留主对话原文供检查，不会擅自靠猜测抽取结论。

## 存储、费用和目前限制

- 每个工作区保存最近一个闭环，最多两轮修改、7 条阶段记录。开始新闭环按钮明确提示替换记录，先导出重要记录。
- 记录存在 DSH 设置中，不写入插件源码，也不随代码备份到 GitHub。普通“项目记忆”导入/导出不会携带闭环执行状态；闭环 JSON 只支持导出查看，不恢复自动权限。
- 一次整理 + 每轮最多两次模型任务；最多两轮。轮次限制不是费用限制，也不控制模型单次任务内部的工具调用次数。请同时使用宿主的用量和权限控制。
- 本版通过模型读稿复核，尚无独立 PDF/OCR 解析器、稿件哈希验证或确定性差异校验。“给出证据”不等于“插件已独立核实证据”。
- 不自动运行真实实验，不自动投稿，不自动把机器结论写成研究者确认。需要作者承担判断的地方会保留待办。
- 当前审稿闭环界面及任务协议以中文为主，其余已有界面保留原有语言行为。
