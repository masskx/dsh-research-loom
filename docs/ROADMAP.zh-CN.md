# 后续改进方向

当前版本为 0.9.0，提供三场景引导及“审稿结果 → 修改新稿 → 只读复核”的两轮受限闭环。下面列出计划方向，不表示这些功能已经实现，也不承诺发布时间。
优先用真实论文项目验证完整流程，再扩大功能范围。

## 优先级 1：可信材料与真实产物回流

现状：根据路径盘点材料，人工纠正归类；普通任务结束后识别新增路径。审稿闭环能够关联真实完成的消息、回收结构化意见与模型报告的修改证据，但不独立核验文件内容。

计划：接入可用的 PDF/DOCX 读取器，记录全文、仅摘要、不可读和书目核验状态；
利用文件内容指纹检测原文件修改，维护任务与实际产物的对应关系。

验收：同一份论文更名或更新后不重复计数；扫描版 PDF 不被标成已读全文；
修改原文件后能看到变更，失败任务不冒充完成。

## 优先级 2：跨模块连续工作

现状：通用流程仍手动保存项目记忆；审稿闭环内部已传递问题与阶段结果。通用项目迁移使用 JSON 快照，闭环另行导出，不恢复自动执行许可。

计划：将结构化项目状态保存在论文项目目录，使用稳定项目标识；
从任务结果提取候选结论、方向与待办，经用户确认后更新记忆，支持回滚和恢复。

验收：移动项目目录或换电脑后仍能继续；研究方向变更可追溯；
文献综述、研究设计和写作模块引用同一份已经确认的研究问题与证据。

## 优先级 3：投稿和返修闭环

现状：支持通用、SCI/EI 建议量表及具体刊会要求；审稿闭环按原问题编号保存意见、行动、位置、证据与状态，支持一次授权后修改及只读复核，最多两轮。

计划：将作者指南的来源、版本和日期结构化；建立投稿附件清单；
把现有意见—修改记录扩展成独立稿件差异核验、正式逐点回复信及投稿附件管理。

验收：格式符合度与学术质量分开评价；无证据项明确待评估；
每条回复能定位到实际修订，最终投稿由研究者操作确认。

## 持续优化：使用体验与发布可靠性

- 在已有三场景使用向导上增加工具能力检查，直接说明哪些工具实际可用、缺少什么；目前仅提供使用要求说明。
- 优化侧栏宽度、长列表、键盘操作、深色模式和窄屏布局，避免干扰主对话。
- 支持更细粒度的材料“不适用”判断、批量归类和重复文献识别。
- 增加 Windows / macOS / Linux 安装验证及 DSH 版本兼容性检查。
- 建立带真实输入与人工评价的研究任务样例，测量引文真实性、证据可追溯性和建议可行性。

建议的下一次小版本目标：先完成“读取状态 + 原文件变更识别”，
用一个从文献整理到研究计划的项目验证结果，再开始扩大投稿管理功能。
