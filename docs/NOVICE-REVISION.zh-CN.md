# 第一次返修：从原始意见到可检查的修改

适用于 0.10.0。目标是帮助已有初稿的作者完成一轮小范围返修；模型仍负责读稿和理解，插件负责材料选择、任务记录、文件检查和衔接。

## 1. 确认本轮材料

打开“开始 → 论文返修 → 梳理审稿意见”。从候选里选一份主稿、添加原始审稿意见和编辑决定信，也可以填写相对工作区的路径。最多 20 份意见文件。

候选文件名不代表已读全文，也不会自动确定权威版本。没有确定轮次可以留空；对应关系可选“不知道，先帮我核对”或“历史意见，需要检查是否仍适用”。混入意见文件的作者回复草稿需要在阅读时分开识别，草稿中的实验声明不能当作事实。

点击“确认本轮材料”，再点“读取原始意见并建立返修清单”。第二个按钮直接调用当前模型；此阶段只读材料，不改论文。输入框有未发送的草稿或存在运行中任务时不会启动。

更换主稿、意见、轮次或对应关系会撤销材料确认。旧返修记录仍明确属于原材料，不会自动变成新稿的返修计划。需要新一轮整理时先导出旧记录。

## 2. 看懂一条意见，选择一小步

结果回到下方任务卡，顶部“查看返修任务与实际改动”可以直接定位。每项说明：

- 原意见及文件、审稿人、原编号、原文位置；拆分任务仍保留原意见编号。
- 意见在当前主稿中是否适用，以及用普通语言解释的要求。
- 应采取什么行动、还缺哪些证据、怎样检查是否完成。
- 属于文字修改、真实实验/分析还是作者决定。

“先选择一项文字任务”按模型建议的优先级选一项；作者仍须核对依据。也可以自行勾选，最多 20 项。需要真实实验或作者决定的事项无法勾选成自动文字修改。

例如，正文和表格的 shot 设置矛盾时，应先找实验配置核对，不能默认某一处正确。统计结果缺少重复次数、标准差含义或原始记录时，补写流畅文字不能代替证据。

## 3. 修改与检查

选好任务后点击“授权本轮修改并执行”。不必手写意见编号和复杂范围；补充要求可以展开填写。每轮最多执行一次修改和一次只读复核，最多两轮修改。每次都是模型任务，轮数不等于固定 token 或费用上限。

模型应保留原稿并生成独立新稿。宿主核验稿件存在、位于当前工作区并具有独立文件身份；其他问题仍保留在记录中。工作台将完成状态标为“模型报告”，不自动变成作者确认。

点击“查看实际文件差异（不调用模型）”，可比较当前两份 LaTeX、Markdown、TXT 等 UTF-8 文本：

- 宿主读取文件并计算指纹，显示首处至末处变化的覆盖区域；中间可能包含未变化的行。
- 每份文件最多 512 KiB，每侧预览最多 8,000 字符，超出时明确提示。
- Word/PDF、非 UTF-8 文本不会伪装成比较成功。需要在对应编辑器检查。
- 只比较所选的两个文件，不递归比较 LaTeX 子文件，不编译论文，不证明学术正确性，也不证明原稿在修改前后始终未变。

## 4. 中断后继续

服务错误或最终回复格式不完整时，插件保留最后一份已接受的意见清单，不会把中途文件生成当成任务成功。

如果修订稿已经生成，在“中断后继续检查已有稿件”填入该文件路径。可以先查看实际差异，再点“只读检查这份稿件并恢复记录”。这会核验文件身份，并发送一次只读模型任务，不重复改稿，不补造“修改成功”的历史记录。

若修改阶段已完整成功、只有复核失败，可点“重试上次只读复核”。再次失败会停下，不无限调用模型。收起工作台、刷新或切换会话后，不会自动恢复调用许可。

## 5. 带走结果

“导出返修检查清单与回复填写模板”生成 Markdown，保留意见、来源、模型报告的状态、行动、证据和作者检查项。回复栏是待填写模板，不是已经完成的正式回复信。需要证据支持的声明，确认实际完成后再写。

“导出本闭环记录”保留结构化记录，供本地备份查看。设置和导出可能含私人审稿内容，不应提交到插件公开源码仓库。
