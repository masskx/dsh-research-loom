# 用已有论文项目试用 Research Loom

适用于同一目录包含论文、代码、实验记录与历史审稿意见的交接项目。先跑通一轮可核验的小范围修订，再扩大范围。

## 1. 固定测试基线

复制需要的材料到独立工作区，保留原项目。使用交接说明和作者确认确定主稿；同名 main.tex、Word 源稿、已编译 PDF 和重写提纲可能不是同一版本。不要按文件名或修改时间自动选定。

建议起步结构：

```text
paper/main.tex                 # 本轮唯一基线，以及编译所需的图和引用
paper/refs.bib
reviews/reviewer-comments.md   # 本轮意见；注明来源、时间和原编号
context/project-brief.md       # 版本、目标、允许修改范围、证据边界
code/                          # 需要核对的源码
results/                       # 新的修改对照和待核验记录
```

历史审稿人原文、作者拟写回复、已经做完的实验记录应分别注明来源。拟写回复中的“已补实验”不能替代实验记录。数据集和权重按任务需要提供，只有代码不能证明结果已经复现。

## 2. 盘点与记录

1. 在 DSH 添加测试工作区，打开论文工作台。
2. “材料”重新扫描；如提示不完整，限定扫描子目录并排除数据缓存、模型权重、历史备份等本轮无关目录。
3. 搜索主稿、审稿意见和参考文献，检查并修正归类。归类只是导航，不是全文读取证明。
4. 在“更多 → 项目记忆”记录主稿相对路径、意见来源、研究边界和暂不处理的问题。不要把待核验结论填成研究者已确认结论。

0.9.3 会优先将与任务有关的材料放入最多 60 项的候选路径。它仍是抽样；版本多时必须明确告诉模型本轮基线。

## 3. 发起只读诊断

0.10.0 推荐选择“开始 → 论文返修 → 梳理审稿意见”，确认主稿与原始意见文件，并将旧意见标为“历史意见”或“不知道”。然后直接建立返修清单，见 [第一次返修指南](NOVICE-REVISION.zh-CN.md)。若使用通用对话草稿路径，检查并补充：

```text
本轮唯一基线为 paper/main.tex，审稿资料为 reviews/reviewer-comments.md。
这是历史意见对当前稿的适用性检查；先标出已处理、仍适用和待确认项。
先读取实际稿件和相关表格，仅诊断，不改文件、不运行训练。
保留原审稿人、原编号和意见原文，区分文字修改、补实验和作者决策。
列出证据位置；不能将历史拟写回复当成已完成实验的证据。
```

手动发送。第一次发送后 DSH 会从空白输入页进入会话页，需要时重新打开工作台。检查模型实际读取的文件以及最终回复，不把工具失败或中断的片段当作完整结果。

## 4. 接续一次修改与复核

在同一会话打开“已有审稿结果？接着修改与复核”，选择刚结束的回复，填写 `paper/main.tex`，点击“整理这份审稿结果”。检查结构化计划后，再填写一次明确授权，例如：

```text
仅修改确认的摘要问题，创建完整独立新稿 paper/revised-1.tex。
摘要以外的正文、数字、表格、公式和引用保持不变，保留原稿。
不补造实验或显著性结论；其他意见继续保留原编号和待办状态。
生成实际修改对照，随后只读复核新稿。
```

点击“授权本轮修改并执行”，保持工作台打开。一次诊断、一份计划、一轮修改和一次复核通常是四次模型任务；每次任务内部还可能有多次模型/工具调用，不能按“四条消息”估算固定费用。涉及宿主审批时检查实际操作及路径。

## 5. 验收再扩大范围

- 确认新稿真实存在，原稿没有被覆盖；外部备份和哈希可以辅助核对。
- 查看实际差异，确认它限于授权范围；LaTeX 重新编译并检查排版、引用和表格。
- 复核记录必须指向本轮新稿并保留全部问题编号。实验和作者决策没有新证据时不能通过。
- 导出闭环记录保存，再由作者决定下一轮文字修改或实验任务。不要把一轮结束当成论文可以投稿。

本插件独立核验文件身份，0.10.0 可只读比较当前两份 UTF-8 文本稿件。写前快照、统计重算、LaTeX 子文件对照与完整 PDF 排版验收仍由外部完成，不能宣传为插件自动完成。
