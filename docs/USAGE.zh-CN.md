# 新手使用指南：从你的当前状态开始

先完成[插件安装](INSTALL.zh-CN.md)，在 DSH 打开论文工作区，然后点“论文工作台”。
无需先配置评分、流程模板或斜杠命令。

## 共同操作：准备 → 发送 → 核验 → 下一步

1. 在“开始”选择场景，阅读当前任务的目标和“需要准备”。默认从第一步开始，也可用任务下方的步骤选择框随时切换。
2. 必要时填研究主题，点“准备任务到对话框”。建议基于当前场景、步骤、候选材料和项目背景生成；可以自己修改。
3. 核对文件路径、目标与授权范围，在 **DSH 主对话**发送。工具需要权限时按实际任务判断后批准。
4. 阅读回复，检查生成文件和证据。无法读取的文件、未完成的实验都不能当作完成。
5. 核验后在任务下方的步骤选择框切换下一步。引导步骤只是导航，不会自动改变“流程”里的研究状态。

想保留方向、结论和待解决问题，可到“更多”展开“项目记忆（可选）”，编辑后移开焦点保存。
后续任务会带上这些记录；模型仍需核验，不把记忆当作已证明的事实。
切换场景或步骤后重新准备任务，会替换上一段未编辑的插件提示词，保留其前后自行补充的文字。
如果改动了提示词内部，或刷新页面后插件无法识别原草稿，会先询问是否替换整份草稿；可取消保留原文，不会自动叠加两段任务。确认过程中再次编辑草稿会阻止替换，需要重新准备。

## 场景一：我已经有自己的论文

准备：自己的完整初稿；有条件时附参考文献库、图表及方法/数据说明。
建议将自己的稿件放在 `paper/`，参考论文放在 `sources/`，但目录名不是强制要求。

### 1. 检查论文

选“已有论文 → 检查论文”，准备任务。可在草稿追加：

```text
我的初稿是 paper/main.docx，sources 中是参考论文。
先重点检查研究贡献和讨论是否有充分证据，不要直接大幅重写。
```

模型应先确认稿件身份与可读性，再给诊断清单。验收时看每个问题是否能定位到章节、
是否区分“缺少证据”和“表达欠清晰”。多篇候选无法区分时，应先询问你。

### 2. 逐项改进

确认本轮优先事项后选“逐项改进”，例如只改引言和讨论。
核对新稿与修改对照：有没有改动数据、夸大创新、添加未验证引文；需要实验的项是否仍列待办。
保留原始稿，不把润色视为完成实验。可以停留在此步重复多轮。

### 3. 准备投稿

在“具体投稿目标与作者指南”填写刊会名称、官方链接、指南日期和文章类型，也可在对话中补充。
选“准备投稿”，检查输出是否包含格式、匿名、附件、伦理/数据声明和无法核验项。
投稿信为草稿，作者名单和声明须本人确认。最终由作者提交，插件不代投。

## 场景二：从零开始，没有任何文件

准备：空工作区即可。研究兴趣、基础、时间、能用的数据可以边聊边明确。

### 1. 明确方向

选“从零开始 → 明确方向”，主题没想好可留空。发送后先回答不超过三个澄清问题。
例如：“我是计算机专业新手，三个月时间，没有自有数据，希望使用公开数据做可复现实验。”
先判断方向的可行性，别急着让模型写一篇完整论文。

### 2. 收集与整理

填入确认的主题，选择资料来源：

- **只整理我提供的论文**：把论文放入工作区，到“材料”重新扫描。要求模型读可访问内容，建立文献矩阵、记录创新点与局限，不移动或改名原件。
- **联网检索**：使用宿主的检索工具。检查题名、作者、年份、DOI/URL、检索日期，区分全文与摘要。
- **已有资料 + 补充检索**：先整理本地，再针对缺口查找并去重。
- **自动**：有候选材料时先本地整理，没有时联网；判断只基于路径，若候选不是参考论文，应手动选来源。

默认检索窗口为近五年及奠基文献。要修改窗口或补充约束，展开“更多工具 → 课题起步”，
或直接在准备好的提示词中调整。不能联网时不要把模型记忆当最新检索；先提供可核验来源。

验收：至少抽查关键文献、证据出处和研究缺口。模型提出的创新点只是候选，不是新颖性证明。

### 3. 制定研究计划

明确你采纳的方向和证据，选择“制定研究计划”。验收问题/假设、方法、资源、伦理、里程碑和最小下一步是否匹配现实。
理论或综述研究不强制要求实验数据。确认后记录项目记忆，再到“流程”选择研究设计、写作等模块继续。

## 场景三：论文返修

准备：投稿原稿、编辑决定信、完整审稿意见；如果不是第一轮，说明每份文件的轮次。
审稿资料可能保密，先确认刊会和机构是否允许交给当前模型服务处理。

### 1. 梳理审稿意见

选“论文返修 → 梳理审稿意见”，发送时补充期限和轮次。
验收是否保留各审稿人的原文与原编号，是否遗漏决定信要求，是否把复合意见拆成可执行事项。
缺少关键材料时应先补齐或明确未知，不虚构意见。

### 2. 落实修改

确认计划后按优先级修改。实验、数据分析需要真实执行；插件不能把建议写成已完成结果。
每条意见应对应实际修改、新稿位置、证据或有理有据的讨论；未采纳项由作者决定。
建议保留各轮新版本和意见—修改对照表，避免覆盖投稿原稿。

### 3. 核对回复信

提供实际修订稿和修改记录，生成逐点回复草稿。
检查每个“我们已……”是否有证据，页码是否对应最终版，必要时用节标题及段落定位。
核验未完成项、遗漏意见、回复与稿件不一致及附件要求，最后由作者审阅和提交。

## 材料、进度和评分不要混淆

### 审稿任务已经返回结果，下一步怎么办？

不需要再自己把审稿意见拼进另一段提示词。保持在原会话，展开“开始”下方的审稿闭环：
选择完成的审稿回复 → 整理这份审稿结果 → 查看问题清单 → 填写授权文字修改范围 → 执行本轮修改与自动复核。
插件会回收每轮完整回复，展示意见对应的修改位置、证据和剩余问题。每轮重新授权、最多两轮；不是无人值守的无限改稿。
这与上方“准备任务到对话框”不同，闭环按钮直接发出模型任务。完整说明见[审稿闭环指南](REVIEW-LOOP.zh-CN.md)。

“材料”是路径盘点；“流程”中的缺失是预期材料类型未被发现，并不一定真的缺少研究工作。
可纠正分类、调整扫描范围，将不适用阶段排除。研究状态由你核验后确认，独立于文件数量和场景步骤。

SCI/EI 评分仅为建议量表；先明确具体刊会指南，再让模型读取正文并分项给证据。
没有证据的项应标无法评价，不将材料百分比当录用概率。

新手引导只准备草稿，不记录自动任务生命周期。直接运行的模块任务才出现在“最近任务”；
它的新增候选文件不包含原文件修改，也不证明文件一定由该任务生成。结果优先以对话和实际文件为准。
