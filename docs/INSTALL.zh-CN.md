# 插件安装与排错

本指南假设 **DeepSeek Harness 已经安装好**。这里只安装研序插件，不重复安装宿主。
普通用户不需要下载源码、安装 pnpm 或运行构建。本版为 0.9.0，已验证 DSH 0.1.1-rc.2；其他版本需自行核验兼容性。

## 1. 确认安装位置

在运行 DSH 的电脑打开 PowerShell 或系统终端，检查：

```bash
dsh --version
git --version
```

需要 Git、宿主所需的 Node.js 环境，以及可访问 GitHub 和包下载服务的网络。
若找不到 `dsh`，重新打开终端并按宿主安装说明检查 PATH，不需要先改插件代码。
若在服务器部署 DSH，请登录服务器执行安装命令，不是在访问网页的客户端电脑安装。

## 2. 安装到 Web profile

等待研究任务结束，在运行 `dsh web` 的终端按 `Ctrl+C` 停止服务，再执行：

```bash
dsh plugin --profile web add github:masskx/dsh-research-loom
dsh web
```

浏览器打开终端实际显示的地址；保持服务终端运行。安装和启动必须使用同一个 `web` profile。
插件通过 `cordis.patch.yml` 加载服务端和已构建的浏览器模块，不另开服务端口。
仓库名是 `dsh-research-loom`，内部包名仍为 `dsh-academic-research-skills`，不要用同名 npm 包替代本仓库。

## 3. 确认安装成功

1. **设置 → 插件 → 插件配置** 出现 **Academic Research Skills**，开关处于开启状态。
2. 在 DSH 添加/选择论文文件夹，进入该工作区的对话。文件夹可以为空。
3. 空白会话输入框上方或已有会话标题栏出现“论文工作台”。点击后，右侧“开始”显示三个场景入口。
4. 选择场景后能看到准备材料、预期结果和“准备任务到对话框”。点击会填入草稿；需要手动发送才会生成。
5. 审稿回复结束后，可在“开始”下方展开审稿闭环，选择该回复并整理问题。确认修改范围后能自动修改新稿、只读复核。闭环直接执行会使用模型额度，详情见[闭环指南](REVIEW-LOOP.zh-CN.md)。

可选检查：输入 `/` 可以找到 `/ars-outline` 等命令。**不要求使用斜杠命令**，自然语言和工作台按钮均可使用。

## 4. 真正开始研究前

- 确保普通 DSH 对话能调用所选模型。插件没有自带凭据或额度；生成会使用模型并可能产生费用。
- 确保宿主能访问论文文件夹。扫描只是路径盘点，不能说明已读过正文。
- PDF/DOCX 全文读取、联网检索由宿主工具负责。不能解析时可提供可读文本；不能联网时先走本地资料整理。
- 无需固定目录模板。多个项目混放时，可到“材料 → 扫描范围与排除目录”限定论文子目录。

接着按 [三种场景使用指南](USAGE.zh-CN.md)开始，不需要先设置全部流程和评分选项。

## 更新、停用和卸载

旧上游版本与本项目内部包名相同，应更新同一个插件，不要并行配置两个 bundle。
等待任务结束并停止 DSH 后更新：

```bash
dsh plugin --profile web add github:masskx/dsh-research-loom --force
dsh web
```

更新不主动删除现有项目配置。设置保存在 DSH 设置文档中；重要项目可先用
“更多 → 更多工具 → 导出 / 导入项目记忆”导出 JSON。论文文件需要自行备份。
配置迁移不包含正文、会话任务历史或审稿闭环；闭环记录需在闭环面板单独导出供备份查看。

暂时停用请关闭设置中的 **Academic Research Skills**，工作台、技能和命令隐藏，项目配置保留。
卸载命令如下，执行后重启 DSH：

```bash
dsh plugin --profile web remove dsh-academic-research-skills
```

## 常见问题

### 只有开关，没有工作台

检查是否选了有实际路径的工作区、开关是否开启、安装与启动是否在同一 `web` profile，
以及安装后是否完整重启服务。最后强制刷新浏览器。若仍显示旧版，停止服务，用更新命令重新安装。

### 点击任务没有开始生成

“准备任务到对话框”**只填入草稿**。检查后在 DSH 手动发送，在主对话看回复与权限提示。
“生成模块结果”等直接运行按钮在已有草稿时也不会自动发送。未编辑的上一段插件任务会被替换；已编辑或无法识别的草稿会先询问。
扫描中、对话执行中会禁用相关操作；扫描失败时到“材料”重新扫描。
模型、凭据或工具报错时先按对话提示解决，插件不能替代这些宿主能力。

### 返修仍显示选题未完成

“开始 → 论文返修”是独立的任务引导，不要求补走选题阶段。
“流程”中的研究状态是研究者独立确认的；可以将已有阶段确认，或标记不适用。
自动发现稿件、切换引导步骤都不会替你确认学术完成度。

### 文件没有被识别或材料完整度很低

文件名仅为线索，不是正文证据。到“材料”纠正分类、排除无关文件、检查扫描范围；
新放文件后点“重新扫描”。默认过滤代码、依赖和缓存目录，单次候选最多 2,000 条，不保证穷尽。
材料完整度不是论文质量。深度评分需在读到正文后提供具体证据，SCI/EI 预设也不能替代目标刊会指南。

### 安装失败或端口报错

安装失败时检查 Git、Node.js、GitHub 与包下载网络；不要把密钥写进命令。
`EADDRINUSE` 表示端口占用；Windows `listen EACCES` 也可能是系统保留端口。换一个可用端口，例如：

```bash
dsh web --port 3001
```

看到 `registered 20 skills (enabled)` 表示技能注册成功，不代表端口或模型服务一定正常。
反馈时提供系统、版本、复现步骤和脱敏日志：[Issues](https://github.com/masskx/dsh-research-loom/issues)。

### 远程使用有什么不同

安装命令相同，但工作区指向服务器上的文件夹。本机论文需要你自行安全传到服务器。
模型及文件读取在宿主环境执行。由管理员配置网络监听、鉴权和反向代理，
不要将未受保护的 DSH 暴露到公网。插件无需独立开放端口。
