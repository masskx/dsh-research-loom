# 从 GitHub 安装到 DeepSeek Harness

这份说明面向只想使用插件、不参与开发的用户。正常安装不需要 clone 仓库，
也不需要运行构建命令。

## 1. 准备环境

安装方式适用于 Windows、macOS 和 Linux；当前实际验证环境为 Windows。
请先安装 Node.js 20 或更高版本（推荐当前 LTS）及 Git，然后在终端中执行：

```bash
node --version
npm --version
git --version
npm install -g @deepseek-ai/dsh@0.1.1-rc.2
dsh --version
```

最后一条命令应输出 `0.1.1-rc.2`。如果终端提示找不到 `dsh`，请关闭并
重新打开终端，让全局 npm 可执行目录进入 `PATH`。

## 2. 从 GitHub 安装插件

本指南安装的是 **研序 · Research Loom 0.7.0**。仓库为
[masskx/dsh-research-loom](https://github.com/masskx/dsh-research-loom)，
内部插件包名仍为 `dsh-academic-research-skills`。设置卡片沿用 **Academic Research Skills**。

DSH 的 Web 界面使用名为 `web` 的 profile。执行：

```bash
dsh plugin --profile web add github:masskx/dsh-research-loom
```

该命令会把 GitHub 仓库作为 DSH profile 依赖安装，并自动读取仓库中的
`cordis.patch.yml`、`lib/startup.js` 和已经构建好的 `lib/client.js`。
普通用户不需要运行 `pnpm install` 或 `pnpm run build`。

安装旧版 `dsh-academic-research-skills` 的用户，先停止 DSH，再使用下文更新命令。
新旧版本内部包名相同，请作为同一个插件更新，不要并行配置重复的 bundle。

## 3. 启动 DSH

```bash
dsh web
```

终端显示访问地址后，在浏览器中打开该地址。默认通常为本机
`http://127.0.0.1:3000/`；如果端口已被占用，DSH 会显示实际地址。

不要关闭正在运行 `dsh web` 的终端。需要停止服务时，在该终端按
`Ctrl+C`。

首次运行还需要按 DSH 引导配置模型服务及凭据，在对话页选好可用模型。
插件不附带模型额度或 API Key；扫描路径不调用模型，生成任务使用当前模型并可能产生费用。
联网检索与 PDF/DOCX 全文读取需要宿主提供相应工具，安装插件本身不会安装独立解析器或数据库订阅。

## 4. 首次使用

1. 在 DSH 左侧添加或选择论文所在的工作区。
2. 进入该工作区的对话。
3. 空白新会话会在输入框上方出现“论文工作台”入口；发送第一条消息后，入口会
   移到会话标题栏。点击后都在右侧展开同一个学术侧栏。
4. 侧栏会先按文件路径和类型自动盘点论文材料，再显示当前阶段、已有/缺失材料、
   流程模式和材料完整度。
5. 根据论文类型选择“智能匹配”“实证研究”“理论研究”“综述论文”或“自定义”。
6. 根据投稿目标选择“通用学术规范”“SCI 期刊”或“EI 会议”。
7. 切到“流程”，点击任一阶段查看材料和动态任务建议；可先“填入对话框”审核，也可直接
   “生成模块结果”。
8. 不查看时点击侧栏右上角的 `×` 收起。收起后只保留标题栏入口，不占用或
   遮挡主对话。

### 空白课题如何起步

0.7.0 顶部有“概览 / 材料 / 流程”。在“材料”纠正文件归类、限定论文子目录；
在“流程”查看材料缺口并确认实际研究状态。已确认状态不会被重新扫描覆盖。

如果当前工作区没有明确论文产物，工作台会自动展开“课题起步”：

1. 已经收集了一些论文：把 PDF、DOCX、BIB 或 RIS 文件放入工作区，选择
   “整理已有资料”，点击“重新扫描”，然后填写研究主题或关注点。插件会生成
   文献盘点、文献矩阵、创新点与局限比较、研究缺口和后续计划任务。它不会自动
   移动、改名或覆盖原始论文。
2. 还没有任何资料：选择“在线检索资料”，填写研究主题和现实约束，选择近 2 年、
   近 5 年或不限年份的检索时间窗，然后点击“启动课题研究”。模型会先核验来源和
   书目信息，再总结最新进展与候选研究方向；主题不够明确时，会先提问澄清。

两种方式都可以点击“填入起步任务”先检查完整提示词。在线检索是否能访问具体
数据库取决于当前 DSH 会话可用的网页和研究工具；插件不会绕过数据库登录、付费墙
或访问权限，也不会把搜索摘要伪装成全文证据。

也可选择“已有资料 + 补充检索”，先整理本地文献，再针对缺口联网补充。
从工作台直接启动后，到“概览 → 最近任务”看执行状态和新增候选产物；模型执行结束
不等于研究通过核验。核验结果后可验收任务，再到“流程”独立确认阶段。
如果只有对话文字或修改了原文件，请在对话里检查，新增路径清单不会反映这类变化。

在“项目记忆”记录已确定方向与待解决问题，后续模块会继承这些记录。通过
“导出 / 导入项目记忆”下载 JSON，与论文一起保存，迁移后预览并应用。
导出不含论文正文和会话任务记录，保留原目录结构才能继续匹配材料。

插件不要求必须使用斜杠命令。论文工作台按钮、普通自然语言对话、模型自动调用
技能和 `/ars-*` 命令都可以独立使用。

## 5. 确认安装成功

可用以下三种方式确认：

- 对话页标题栏出现“论文工作台”入口；
- “设置 → 插件 → 插件配置”中出现 **Academic Research Skills** 开关；
- 在对话框输入 `/` 时，可以找到 `/ars-outline`、`/ars-full` 等命令。

设置开关关闭后，技能和 `/ars-*` 命令会即时注销，论文工作台也会隐藏；
重新打开即可恢复，不需要重新安装。

## 6. 更新

先停止正在运行的 `dsh web`，然后执行：

```bash
dsh plugin --profile web add github:masskx/dsh-research-loom --force
dsh web
```

重新安装不会主动删除 DSH 设置文件（默认 `$DSH_HOME/settings.yaml`，未指定
`DSH_HOME` 时为 `~/.dsh/settings.yaml`）中已经保存的项目
流程和目标标准。

如果 Git 缓存导致界面仍是旧版本，可彻底移除后再安装：

```bash
dsh plugin --profile web remove dsh-academic-research-skills
dsh plugin --profile web add github:masskx/dsh-research-loom
dsh web
```

## 7. 卸载

```bash
dsh plugin --profile web remove dsh-academic-research-skills
```

卸载后重启 `dsh web`。

## 常见问题

### 安装后没有看到论文工作台

依次检查：

1. 是否在安装命令和启动命令中使用了同一个 `web` profile；
2. 是否在安装后完整停止并重新启动了 `dsh web`；
3. “设置 → 插件 → 插件配置”中的开关是否开启；
4. 当前会话是否已经选择了一个有路径的工作区；
5. 浏览器是否仍缓存旧页面，可执行一次强制刷新。

### 安装成功，但点击任务没有生成研究结果

先在普通 DSH 对话中发送一条简短消息，确认模型配置和网络正常。再检查：

- 输入框是否已有草稿：此时插件只追加建议，需要你检查后手动发送。
- 是否仍在扫描或已有任务正在执行：等待完成，或在概览中检查任务状态。
- 是否出现模型、凭据、工具不可用或权限提示：按 DSH 对话给出的原因处理。
- 如果任务没有新增文件，结果可能在对话中，或修改了原文件；当前产物清单只识别新增路径。

### 安装命令失败

确认 Git、Node.js 和 npm 可用，能访问 GitHub 和包下载服务，并使用本指南中的仓库地址。
Windows 安装全局 DSH 后若命令找不到，重新打开终端。保留完整错误信息到本仓库 Issues
反馈，提交前移除凭据及私人路径。不要把 SSH 私钥或 API Key 写入安装命令。

### 材料状态不准确

自动盘点只读取工作区文件索引中的路径和文件类型，不读取正文。建议使用清晰的
目录和文件名，例如 `literature/`、`methods/`、`data/`、
`results/`、`submission/`、`reviewer-comments.docx`。侧栏中的结果是
导航和完整度初评，不是 SCI/EI 论文质量结论。

### SCI/EI 分数代表什么

圆环百分比只代表当前流程下的材料类型完整度。“按此标准深度评分”才会把透明
量表和文件引用交给模型，要求它读取正文后评估；无法核验的项目会被要求标为
“不可评分”。

### 远程服务器如何安装

安装命令相同。请根据服务器的访问控制方式配置 DSH Web 的监听地址、反向代理和
鉴权，不要把未受保护的 DSH 服务直接暴露到公网。插件本身不需要单独的服务端口。
