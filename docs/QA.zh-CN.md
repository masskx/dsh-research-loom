## 通用验证方法

运行 `pnpm run verify` 验证材料纠正、范围排除、研究状态、任务状态、产物差集和记忆迁移。

隔离浏览器验证入口：

```bash
node scripts/serve-ui-fixture.mjs
```

打开终端打印的本地地址。此页面仅模拟 DSH 状态，不访问论文目录、模型或真实 DSH 设置。

验收路径：

1. 空目录打开工作台，确认首页显示三个场景，不显示评分或设置卡片；高级工具移到“更多”。
   逐一选择“已有论文 / 从零开始 / 论文返修”，检查九个步骤的准备材料、预期结果和任务草稿。
   点“准备任务到对话框”不能自动启动；切换步骤不能确认研究状态。
   “从零开始 → 收集与整理”分别测试本地、联网和混合来源。
2. 在“更多 → 更多工具 → 课题起步”直接启动研究，点击“模拟完成并产出文件”，确认新增 `literature/research-gap.md`
   出现在最近任务，任务待检查而不是自动确认。
3. 在“更多 → 最近任务”验收任务，展开项目记忆填写方向，在流程确认选题；填入文献模块任务，确认携带记忆。
4. 切换场景重新准备时替换旧插件任务，保留前后手动文字；已编辑或未知草稿需确认替换，取消时原文不变。
5. 切换第二项目，将 `sources/seed.pdf` 归为参考文献库，重新扫描，确认选择保留。
   代码审查 YAML 默认被排除。返回第一项目，确认记忆、场景、步骤和阶段仍在。
6. 模拟失败，确认最近任务显示失败。控制台可通过 `fixture.setFailSave(true)`
   模拟保存失败，检查错误提示和原记录保留，然后恢复为 `false`。
7. 在更多工具导出项目 JSON，重新导入预览后应用，确认记忆、场景和归类恢复且任务历史不被导出覆盖。

真实 DSH 页面另外检查侧栏开合、四视图、配置保存和草稿填入。隔离会话验证不代表
在线文献检索质量或 PDF 解析能力已经经过真实研究任务评估。

## 0.9.1 材料刷新修复（2026-09-10）

问题：DSH 0.1.1-rc.2 的无目录文件补全查询复用每个会话的索引。空项目扫描后，用户从外部放入材料，插件再次发送同样的补全查询仍可能得到旧清单。

修复：新增插件自己的只读扫描接口，由 DSH 根据会话 ID 解析工作区，每次读取实时目录；前端不再使用文件补全索引。新增、改名、删除后的清单会整体替换，原有路径归类与作者确认状态继续独立处理。

- `pnpm run verify`：35 项测试通过。新增真实临时文件系统测试，覆盖同一服务/会话空目录→新增→改名→删除、35 个同级文件、中文与空格子目录、扫描上限、链接隔离、取消和失效目录。
- 本机安装 0.9.1 并重启 DSH；确认仓库与已安装客户端构建文件 SHA-256 相同。
- Playwright 在实际 DSH 的独立空项目中验证：同一会话、无页面刷新或模型请求，材料数 0→1→1（新名称）→0；随后加入 25 个测试文件，全部显示，没有旧文件补全接口的 20 项截断。
- 上述新增文件被识别为“文献综述 · 文献矩阵或研究缺口”；存在文件不自动确认研究阶段。
- 最终真实页面控制台无错误或警告。测试材料、会话截图留在本地 `output/`，未包含在公开仓库中。

可重复的手工验收：打开空文件夹，等待首次扫描，外部新增 `literature/research-gap.md`，点“材料 → 重新扫描”；改名，再扫描；移出项目，再扫描。整个过程保持同一会话，分别检查路径出现、旧路径移除和数量归零。

边界：每次最多 2,000 个文件、10,000 个目录项、2,000 个目录和 32 层深度；不跟随链接。达到上限或跳过不可读取位置时显式提示清单不完整。此修复验证文件盘点与 UI 更新，不评价论文内容或模型质量。
